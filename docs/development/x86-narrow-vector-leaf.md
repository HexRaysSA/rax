# Narrow vector consumers after YMM transfers

The AVX-only YMM0-YMM15 bridge reloads the guest's low 256 vector bits after
a memory helper. On the Windows 10.0.29704.1010 ARM64 validation host, an x64
process executing a subsequent 128-bit instruction can use the old destination
instead of the explicit source or merge operand. This observation is bounded
to that host and build; the translator's internal cause is unknown.

An independent native reproducer loads three distinct values into YMM0,
YMM1 and YMM2, then executes `C4 E2 71 DC C2` (`VAESENC XMM0,XMM1,XMM2`).
For little-endian pairs of 64-bit words:

| Operand/result | Word 0 | Word 1 |
| --- | --- | --- |
| Initial XMM0 | `f0e1d2c3b4a59687` | `1d385c7e8492907f` |
| XMM1 | `1f873f871f877bc3` | `c2d0928fb594f424` |
| XMM2 | `0011223344556677` | `860fb71ee069d178` |
| Required result | `6d0200772b25e1b3` | `94176a5979658012` |
| Observed result | `14dd4845d49e7576` | `5e6633efc2721193` |

The observed result is the AES round of initial XMM0 with XMM2. Capturing
operands immediately before the instruction confirms the correct XMM1 value;
capturing both XMM0 and YMM0 immediately afterwards shows the incorrect result
before RAX's output bridge runs. The same instruction works after XMM-only
loads. Reloading XMM after YMM, using `VZEROUPPER`, or using `VZEROALL` followed
by XMM reloads does not repair the result. An internal `CALL`/`RET` around the
consumer repairs all tested load-width variants, including static and dynamic
code. The unmodified static reproducer passes on the Linux x64 TCG control.

The original native load-width experiment ran 512 cases: 128 XMM-only cases
passed and 384 cases involving YMM loads failed. The internal-call experiment
passed all 512 cases. A production public-API probe passed 64 register-only
cases and failed 64 helper-backed memory cases; adding the internal call in its
generated bytes passed all 128 cases. These are diagnostic observations, not
a claim that the complete native test suites pass.

## Lowering contract

`emit_narrow_vector_leaf` wraps the affected AES, round, scalar-conversion and
square-root memory consumers when the YMM bridge is active and the consumer
width is 128 bits. Other widths and bridge modes retain inline emission.

```text
CALL leaf          ; rel32 = +5
JMP continuation   ; rel32 = body length + 1
leaf:
    consumer
    RET
continuation:
```

The envelope adds 11 code bytes and one transient 8-byte host return address.
Its emission and branch fixup take O(1) time and space beyond the consumer.
The consumer must preserve the enclosing RBP and balance its host stack.
State-backed guest RSP/RBP accesses remain relative to the enclosing RBP.
This internal register convention does not introduce a C ABI callback.
CALL, JMP and RET preserve guest arithmetic flags and vector operands.

The existing full-state native memory-source regressions remain the semantic
oracle, including aliasing, destination upper bits, rounding state and fault
atomicity. The leaf-specific native ADC test checks register preservation and
arithmetic flags across carry and signed overflow, with the bridge enabled
and disabled and with 128-bit and 256-bit widths. It requires no AVX support,
so hosts without AVX can still exercise the call envelope.

## Implemented repair validation

The unmodified public-API probe passes all 128 cases with the implemented
near-call envelope: Windows native PID 656, creation FILETIME
134390292491329330, exit 0. No generated bytes were patched in this run.
The focused Windows x64 library runs pass all 28 tests across the leaf and
the four complete memory-source families, without ignored tests or skip
diagnostics. The macOS x64 leaf test also exits 0 and executes without AVX.

Linux x64 passes the leaf, AES, scalar-conversion and square-root families:
22 tests, with no failures, ignored tests or skip diagnostics. The round
family completes three tests before the host QEMU 11.1.2 process aborts in
`gen_VROUNDSS` on its `!s->vex_l` assertion. Its native round-test process and
the concurrent complete library payload have no terminal native results.
Those interrupted runs are incomplete; the assertions remain unchanged.

Complete library test images compile for Windows, macOS and Linux on both
x86-64 and ARM64. Default-disabled C API checks pass for all six targets;
the Windows ARM64 all-target check and host formatting, Clippy and all-target
build gates pass. Compilation and focused runs do not qualify the complete
process-emulation payloads.
