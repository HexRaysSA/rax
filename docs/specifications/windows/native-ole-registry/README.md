# Fixed OLE registry snapshot

Installed ARM64 `cmd.exe` reaches `NtOpenKeyEx` with a retained MACHINE root,
`SOFTWARE\Microsoft\OLE`, desired access `0x20019`, and options 0. The exact
parent stops with an unsnapshotted-subkey error. This change captures the fixed
`\Registry\Machine\Software\Microsoft\OLE` subtree before guest execution,
including both views, every bounded descendant, values, enumeration metadata
and each key's access profile. Guest key arguments never enter host APIs.

OLE uses the existing complete immutable subtree representation and budgets.
`SnapshotRoot` selects a compile-time subject and shares construction/race
guards with the existing CMD roots. Existing CMD capture interfaces are
retained. Both OLE views name one physical subject: mismatched presence,
not-found class, values, grants, enumeration or complete descendants reject
capture. A known absent key stays distinct from an uncaptured neighbor.
Duplicated handles and retained MACHINE handles retain their original records
after registry catalog replacement. Native handles close during acquisition.

## Independent native controls

`absolute-v1.c`, `missing-v1.c`, `relative-v1.c` and `tree-v1.c` perform only
native reads, queries, opens and closes. The first three reuse the unchanged
retained CMD native types/helpers. The tree producer derives from the retained
CMD tree producer, with its original hash in the source; it selects OLE and
restricts the campaign to HKLM. Expected NT results are recorded by those
programs, rather than generated by the emulator.

The retained corpus measures Windows 10.0.29695 on an ARM64 host using ARM64,
x64 and x86 processes. Per ABI it records 136 absolute opens, 136 absent-child
opens, 12 MACHINE-relative opens and every bounded descendant/reopen case.
The tree records 5,152/5,152/4,416 cases for ARM64/x64/x86, respectively:
`3 × (136 + 136 + 12) + 5,152 + 5,152 + 4,416 = 15,572` recorded open cases.
All eight physical keys occur in both views, with identical values, child
names, access ceilings and security-query outcomes. WoW64 tag transitions
remain distinct from the native 64-bit transitions.

`controls-v1.json` preserves complete reports, image identities and raw stdout
hashes. Its approximately 4.7 MB size retains every result and all per-node
metadata needed for service replay after namespace replacement; it contains
no executable images or embedded build archives. Only acquisition source-path
keys are normalized by dropping `producers/`; report fields are unchanged.
The acquisition metadata records these SHA-256 identities:

- Raw native corpus: `eaf28fea3868bfe3d53ca52071642791f76234fba7e72950c7c366e8da3f21e4`.
- Verified archive: `0263cbb66205a7c8c362b179fe1e37fe4e4fe1e85df28e6ea783a8bcc907cf1f`.
- Controller: `fdff82bcccb9a18751de268c48c804bc3e75ddfaf5efb358768448f49486af4f`.

The controller checks PE machine identities, native handle counts, unchanged
producer inputs and unchanged executable hashes. Failed launch/compiler-lookup
attempts remain preserved separately; they do not qualify native behavior.

## Reproduction and validation scope

From the RAX root, producer identity verification is portable:

```text
python tools/ci/windows_ole_registry.py --verify-corpus
```

Expected output reports seven verified inputs and three retained process ABIs.
On Windows with CMake and Visual Studio installed, capture and replay fresh
observations in a new contained output directory:

```text
python tools/ci/windows_ole_registry.py --output target/native-ole-registry-v1
```

The command preserves per-ABI JSON/stderr and image hashes, then runs the
actual guest dispatcher replay, pure selection tests and installed capture
test. It rejects pre-existing output so evidence is not overwritten. An ARM64
host executes all three ABIs; an AMD64 host executes x64 and x86. CI extends the
existing C API lane and preserves native output as an artifact.

The retained service test checks all 15,572 open cases, canonical names,
grants, tags, values and complete descendant lifetime through duplicated
handles after catalog replacement. Pure tests cover view races, fixed-name
validation, absence classes, descendant identity/access and retained MACHINE
routes. Matching-host acquisition is Windows-specific; the guest model and
retained replay compile and run on Windows, macOS and Linux. Complete local
and CI gates and installed CMD successor comparison are tracked separately;
the first local iteration passes all five new portable OLE tests.

## Scope and remaining work

The fixed snapshot does not admit arbitrary guest host-registry access. Public
C ABI, exported service identities, tool options, embedded defaults and
permission scopes are unchanged. Native acquisition is behind the Windows
adapter; common guest code uses the existing model on all three hosts.

High impact: the installed CMD successor and subsequent Windows startup
requests still require native validation before full process support can be
claimed. Medium impact: live host registry changes during acquisition can
cause a deliberately rejected inconsistent snapshot; capture is not an atomic
transaction over the host hive. Native hardware/profile and product/package
coverage remain separate from retained replay. No unrelated subsystem change
is included.

Microsoft's [Registry Keys Affected by WOW64](https://learn.microsoft.com/en-us/windows/win32/winprog64/shared-registry-keys)
lists OLE as shared from Windows 7/Server 2008 R2 onward. The retained primary
copy is [shared-registry-keys.html](../native-filesystem-registry/shared-registry-keys.html).
The documented shared classification does not substitute for measured NT
key-body tags or access outcomes.
