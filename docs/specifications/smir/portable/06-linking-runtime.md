# Linking and runtime services

Candidate executable profile 0.2 uses ordered runtime roots for sections 2, 4, 5,
6, 7 and 9. Their complete field order and alternatives are in
[schema/runtime/candidate.json](schema/runtime/candidate.json), generated by
`tools/smir-runtime-contract/candidate/schema_build.py`. Every field is present;
options are None or `{some:value}`, not an omitted/default field. Integers are
little-endian; bool is one byte 0/1; UTF-8 and vectors have u32 counts; entity IDs
are u32 and module-qualified. Unknown fields, variants, trailing bytes, malformed
UTF-8, duplicate IDs and noncanonical order reject. No envelope-only decoding,
producer hash, or file-provided callback is executable admission.

ABI2 migration retains envelope0.2/profile2 and runtime payload revision1;
section10 alone uses ABI payload revision2. Read the raw revision word before
schema-dependent records. Historical ABI1 objects reject `WIRE-REVISION` and
cannot count as current semantic rejections. Regenerated fixtures use explicit
source declarations and V2 nominal identities; missing record inputs are never
reconstructed from selected layout outputs. This is an unqualified contract
migration, not executable admission or compiler freeze.

## Identities, declarations and source ABI

LINK-001: A module's logical family is `(namespace,name,abi_major)`. `abi_minor` identifies
a release within that family; it is not a content digest or live generation.
An artifact digest is SHA-256 of `SMIR0.2 NUL`, LE u32 profile 2, then sections
1..10 in order, each LE u16 ID, LE u64 payload length and canonical payload.
Only the 32 bytes of section-2 manifest identity at offsets 4..36 are zeroed.
Dependency records contain no peer digest, so mutually dependent artifacts can
have content identities without a hash cycle. Deployment separately pins every
logical dependency edge to an actual admitted artifact/export binding.

A local entity is `{module:self,id}`. A dependency reference names a consumer-
local dependency slot and declaration ID. That declaration ID is neither a
provider export ID nor the provider's private entity ID. Deployment explicitly
maps all three. Multiple artifacts of one family may coexist; selection is never
implicit first/highest version. Check requested baseline against its min/max
minor range, then actual provider minor, site identity, kind, namespace/name,
source linkage, execution type and source ABI. Weak-null is allowed only for an
undefined weak function/symbol with no matching provider export. Extra/unbound
edges or declarations reject atomically before initialization.

`source_linkage` is exact `none`, `c` or `cpp` on symbols, exports and dependency
declarations. C data uses the ABI's C-compatible boundary projection; C++ data
uses nominal identity. Address-only declarations may reference opaque external
objects without inventing a complete source layout. A complete pointer object
and its incomplete pointee are different cases. Execution shape alone does not
prove C++ function equivalence: actual body ABI function type must agree with the
symbol, and full call plans additionally carry this/VTT, hidden result/byval,
varargs and noundef obligations. The abi_signature option after nominal on all three boundary records names an
actual SELF-local call_signature. Source body plans and foreign import bridge/
signature records are local too; nested nominal dependencies remain qualified.
Actual ABI graph.signature_compatible compares full plans with correct owner
contexts. No omitted plan is inferred from matching execution types.

Source-unit identity is SHA-256 of `rax.source.unit.v1 NUL`, counted strict UTF-8
namespace, family name, project-unit key, and LE u32 ABI major. An absolute POSIX,
drive or UNC path rejects. No path normalization is implicit. Private compiler
symbols use `smir.unit.<unit UID>` namespace and stable local names. Public ODR
identity excludes artifact digest, private IDs and module family. Recompiling or
optimizing a source unit does not by itself change its private source identity.

## Storage, symbols and relocations

Data/TLS segments specify initial bytes, equally sized disjoint poison/undef
masks, zero-fill length/shadow policy, mutability and power-of-two alignment.
Source nominal/layout/binding metadata is either present coherently or absent;
a complete source storage binding proves size, source alignment, physical layout
and whole-object coverage. Source segments use canonical `array<raw8,N>` storage,
not their source value type. Typed subviews have independent value bindings.
All bounds, byte products and alignment calculations use mathematical integers.

Definitions are portable function, data/TLS segment, import, local alias, common,
or independently attested native image code. A function definition joins symbol
execution signature and source type to the actual section-3 body. Import symbols
join the actual section-6 import signature, not just an existing numeric index.
Data/TLS symbols join exact segment extent/alignment/nominal/storage type. Alias
and weak fallback chains require compatible kind/type/source linkage and reject
cycles. A fallback belongs only to an undefined weak/external-weak symbol.

Native definitions contain image SHA-256, domain, RVA offset and code size.
Actual registered image bytes, compiler type graph/prototype, native calling
convention, entry boundary, code generation/hash and CFI facts are independent
admission evidence. Native `win64` calling convention does not imply Microsoft
C++ ABI: MinGW Itanium is also Win64. No native metadata function symbol may be
used by portable `address_of` or function-token construction. Portable calls use
an admitted import/bridge, with the correct code-token domain.

Relocation records specify source data/TLS segment, byte offset, u32 width,
integer precision, kind, qualified target, signed addend, ordered GEP derivation,
check_base:bool, final flags and optional explicit relative inrange. Each GEP
step is offset:i64, check_base:bool, flags, inrange. A true check_base requires
inbounds and validates original allocation/generation/closed extent even for net
zero offset from a nonzero original index. Historical allocation facts are valid
after source lifetime ends; no live-source check is added. All-zero original
indices retain their unflagged zero-offset range operation.

| Kind | Meaning |
|---|---|
| data_address | pointer origin from actual selected object, 8 B; non-inbounds arithmetic modulo2^64; no implicit exposure/inrange |
| data_integer | ptrtointN, widthceil(N/8), truncate/zeroextend64, high unused bits0, no origins, actual object exposure only on publication |
| tls_offset | unsigned4/8 B target PROVIDER module-block segment offset plus addend; no pointer origins or authority |
| function_token/import_token | actual selected issued portable token, 8 B, addend0; no native PC |
| function_integer/import_integer | cast actual portable token to N bits, then integer addend modulo 2^N; no origins; separate CODE exposure |

Derivation retains intermediate pointer-address no-wrap/inbounds/range obligations;
LLVM first validates constant index truncation/scaling/offset arithmetic before
flattening to i64 steps. Known invalid promises initialize poison, not a concrete
alternative pointer. Malformed bounds reject admission. Explicit inrange anchors
at the wrapped result, adds signed bounds mathematically, then clips/intersects;
object extent alone never creates an inrange restriction. Concrete restricted
ptrtoint is UB before publication. Integer width/materialization quotas are
resource policy, not source ABI limits. Other admitted LLVM ConstantExpr forms use the restricted constant initializer
contract below; unsupported expressions receive explicit diagnostics. Original
source-emitted dynamic constructors retain their ordering.

Stage all patches, byte/shadow/origins and exposure effects before one publication.
Reject overlaps, out-of-range source patches, wrong target domain, stale generation,
missing selected member, invalid flags or width. A failed transaction changes none.
Unsigned TLS narrowing overflow rejects. Unresolved weak addresses/code yield null
or an unprovenanced modular data pointer; weak ptrtoint has no object to expose;
missing weak TLS rejects because no provider/table exists. Pointers/tokens are
issued only by actual runtime registries. The private plan retains provider module/
generation/segment-placement leases; integer TLS bytes carry no such authority.
TLS raw helper remains segment-relative, so descriptor adapters subtract verified
module placement rather than adding it twice. Native image relocations belong to
the native loader, not the portable operation-record format.

## Restricted static initialization

Section 5 is exactly payload_revision, relocations, constant_initializers. A
runtime_constant_initializer is id:u32, source_kind:data|tls, source:u32,
offset:u64, layout:SELF entity_ref, function:SELF entity_ref,
association:optional SELF symbol_ref. IDs are sorted and unique. The actual
layout has positive access_bytes; offset+access_bytes fits the source segment.
Private patches use Raw8 accesses at alignment 1, including packed offset 1;
whole-segment source allocation alignment remains independently mandatory.
Only access_bytes are written: allocation tail padding is preserved.

The function is actual verified portable fixed () -> [layout.type], ABI None,
result_noundef false, escape propagate, no_return false, one block, no phi/EH,
and one return. Its closed operation set is constant, copy, freeze, i_add, i_sub,
i_xor, i_mul, icmp, select, extract, insert, extract_element, insert_element,
shuffle, trunc, zext, sext, bitcast, ptrtoint, ptrtoaddr, inttoptr, ptr_offset,
address_of. Calls/helpers, memory access, branches, loops, I/O, FP-environment
operations and physically present opaque/fenv components reject, even unused.
Function-signature edges are not physical value containment. Zero-count empty
values obey the execution type graph's actual component costs.

The association owns the whole destination segment. Independently discardable
COMDAT aliases sharing storage reject. Ordinary weak/common selection also makes
storage discardable; missing required association rejects. Apply the same actual
selection plan to every leaf relocation and constant record before any effect.
Losing storage cannot expose pointers/tokens or invoke an evaluator. Selected
patches cannot overlap each other or selected leaf relocations.

Reserve all selected SCC objects/code tokens and per-TID TLS slots; stage initial
bytes/shadow and leaf relocations; evaluate constants in dependency-SCC/module/ID
order; seal and atomically commit bytes, poison, undef, origins and separate
DATA/CODE exposure sets. Prior staged exposure is visible to later inttoptr;
CODE exposure is mapped through actual registered token/origin/generation facts.
Then run original source constructors/TLS initialization under private cohort
authority; publish the public module namespace last. Data constants run once per
module; TLS constants once per registered logical thread. Data constants cannot
capture ambient TLS. Raw TLS lookup never injects source initialization.

S074 evaluate_initializer independently verifies actual ABI/execution roots and
returns immutable value/Raw8/exposure results. R041 initialization.Store owns the
whole private transaction and issued revision/generation ticket. Constructor and
prepare preflight all staged bytes/origin nodes, including loser-only/no-program
inputs, before cloning. Default reference quotas are 1 MiB, 65536 operations and
100000 component/fact nodes; these are implementation resource limits, not format
or ABI bounds. Every reserved source object, SSA value/output and present component contributes
to the cumulative budget. Plan selected jobs/TIDs and all these costs before
any staging clone; recheck the source revision before copying.
Any precommit rejection leaves bytes, shadow, permissions and exposures unchanged.

The transaction owns only NEW SCC images; their initial bytes/shadow/mutability
must match admitted segment records. It commits once. Existing published/closing
providers are read-only retained inputs: same actual context/generation/pins and
an ALREADY-held opaque lease joined against the actual process lease table's
module/generation/live/kind. Positive aggregate pins alone grants no new lease or
public binding. Prepare and commit bind both fact sets and capability identities.
Old provider images/phases/exposures are never copied, sealed or rolled back.
A leaf may bind an old selected provider; a discarded source may redirect to a
prior winner outside this transaction. Missing, released, forged, unpinned or
changed provider facts reject before publication.

After static commit, retained typed pointers/tokens and integer exposure work for
source-created threads and existing peers before the originating constructor
returns. Public namespace entry remains closed. Constructor effects, callbacks,
threads, published objects and exceptions are never rolled back. Failure closes
new entry and drains child/escaped leases before cleanup/reclamation.

Weak-null address reservations are issued from the actual fixed deployment and
selection. Every issue/use rechecks all retained RootContext snapshots and the
original consumer/reference, including providers with no matching export. SELF
weak/external_weak absence additionally requires no definition/fallback anywhere
in the actual family scope; weak TLS is unsupported. A copied/forged reservation,
cloned context, modified reference, changed selection/binding plan or stale
provider rejects. Null has no object,
code entry or exposure; no token 0 registration is manufactured.

## Whole-group selection and ordinary definitions

LINK-002: `candidate/selection.py` returns an immutable-reference plan before binding,
constructors or code publication. Actual graph comparators and body projections
come from admitted roots. Function bodies use the LLVM owner's actual-wire
comparison projection and the independent runtime alpha normalizer: CFG/SSA IDs
normalize, constants, EH actions, source/call metadata and referenced entities do
not disappear. Data comparisons retain bytes/shadow and normalized relocations.
A producer-supplied body digest is never comparison evidence.

| Selection | Whole-group rule |
|---|---|
| any | first explicit link-input group after ABI checks |
| exactmatch | identical normalized complete member set and content |
| largest | greatest key-member extent, stable first tie |
| samesize | equal key extent, then first group |
| noduplicates | second group rejects |
| nodeduplicate | retain every group; ordinary external duplicate rules still apply |

Mixed any/largest selects largest; other mixed policies reject. Any/largest/
samesize may have unequal member sets. ABI comparison checks the union of all
prior members, including a member first introduced by a nonfirst group. Selection
is indivisible: no union of losing members creates a new group. Referencing a
loser-only member absent from the winner rejects. Function extent is canonical
comparison-view byte length, not future native code size. Source fixed-size data
must retain ABI extent; untyped common/allocation storage may use selected extent.

Default-visibility external groups share process link scope. Hidden/protected
external groups are family-scoped and nonpreemptible. Local members inherit the
exposed key/member scope; incompatible exposed scopes reject. Ordinary external
resolution is family-scoped: strong > common > weak, duplicate strong rejects,
common uses maximum size/alignment after source ABI checks, weak ties follow
explicit input order. Locals do not cross-resolve. Native-image COMDAT belongs
to its admitted native linker and cannot enter portable whole-group selection.

The plan redirects both symbols and actual function IDs. Every direct call,
code/address token, export/declaration binding, relocation, TLS hook and initializer
uses the same plan. Missing versus discarded function IDs are distinct: a private
actual section-3 function without a symbol remains valid; a known discarded
function with no winner rejects. Association with a discarded definition removes
its duplicate init/fini hook. Alias/fallback resolution follows selection.

A live selected definition retains its owner leases. Dynamic admission preserves
a compatible live any/exactmatch winner. Largest/samesize cannot silently replace
live code/storage under existing pointers: replacement-required admission rejects
before constructors. Generation/quiescence-based live replacement is a subsequent
implementation package, not an implied operation of ordinary dynamic loading.

## Process admission, SCC initialization and TLS

LINK-003: Deployment binding accepts dependency cycles and computes dependency-first
strongly connected components. All bindings of an SCC publish atomically; no
constructor observes half a cycle. Within a component, explicit deployment order
and initializer `(priority:u32,ordinal:u32)` determine ordering. Every init/fini
function is portable fixed `void()`. Required source nonthrowing cleanup hooks
use escape=terminate. A failed initialization closes entry, preserves leases and
runs only completed required cleanup; it does not claim transactional rollback of
arbitrary constructor effects.

RT-003: A process has one explicit Linux/Darwin/Windows personality. Every module agrees.
It contains portable SMIR plus zero or one foreign guest ISA, x86-64 or AArch64.
The first foreign admission reserves/pins that ISA atomically before constructors;
it remains pinned after failed init or unload. Concurrent different-ISA admissions
cannot both publish. Multiple foreign compiler/runtime/library domains of the
same ISA/personality are allowed with independently qualified descriptors.

Prepared/admitted metadata can be inspected before executable entry. An existing
issued, generation-pinned TLS binding remains readable as metadata during closing;
new bindings reject closing. Metadata inspection grants no pointer or entry.
Private initialization has an issued cohort: original source TID and actual
source-created/captured-entry delegated TIDs. Every delegated TID first reserves
all required TLS. An unrelated TID cannot enter merely by knowing a module ID.
Closing failure preserves existing cohort access until its children and escaped
code/object/TLS/callback/exception leases drain. Successful publication transfers
surviving leases into normal published-module ownership.

Guest thread admission reserves per-thread module TLS storage, copies template
bytes/shadow and applies TLS relocations before publication. `tls_address_raw`
is a pure pointer calculation against that preissued slot: `base+u64 offset`
modulo `2^64`, preserving object/generation/range even if the result lies outside
bounds. It performs no memory access, allocation, initialization, block or trap;
LLVM uses offset 0. Later dereference validates authority/bounds normally.
Static TLS has no dynamic initializer list. Block-dynamic and namespace-dynamic
initialization use uninitialized/initializing/initialized guards; same-thread
recursive block initialization is source UB, block abort permits retry, namespace
throw terminates. Hooks have exact fixed `void()` shape. Namespace initialization
and TLS destructors have escape=terminate. Guest callbacks run outside TLS/loader
locks; TLS/destructor registrations pin their module generation until thread exit.

Unload closes new entries, revokes tokens/mappings, waits for workers at precise
frontiers and all object/TLS/callback/exception/code/IO leases, then performs
required finalization and reclaims storage/code. A suspended callback or retained
exception may outlive the initiating host handle. Unload cannot free a return PC,
CFI row or callback target still reachable from a parked activation.

### Linking as implemented

`Module::link` in `crates/smir-portable` makes one program of several
modules before any of them runs, and `smir-run --library FILE` does so from
the command line. Each module is an object verified by itself. The first is
the program: its key, its function identifiers and its exports are those of
what is linked. The others are what it and they depend on. This is less than
the sections above ask for; the table says what is done, and
`tests/interp/linking.rs` in that crate checks the rows on both engines, but
for capabilities, weak declarations and foreign processors, which no module
of the tests has.

| Question | As implemented |
|---|---|
| What a module may take from another | Functions, by direct call. A dependency's declaration of `kind` `function` names one by namespace and name and gives its signature; a call whose function refers to the dependency's slot and that declaration is a call of it. A weak declaration is refused as unimplemented when the module is loaded. Declarations of other kinds are not resolved: data, thread-local storage and the address of a function do not yet cross modules. |
| What a module offers | Its defined functions that have a symbol which is neither local nor hidden, under the symbol's namespace and name. |
| Which module answers a dependency | The one among those given whose key has the dependency's namespace, name and `abi_major`, and an `abi_minor` no less than `minimum_minor` and no greater than `maximum_minor` if there is one. None, or more than one, is `LINK_DEPENDENCY`. |
| A function that is not there | `LINK_UNDEFINED` if the answering module offers no function of that name. `LINK_TYPE` if it does and the signature it was declared with is not, structurally, the signature it is defined with. |
| Modules given and not needed | Every module but the first must be needed, directly or through others, by the first: `LINK_UNUSED` otherwise. The order the others are given in does not matter. |
| Cycles | Modules that depend on one another in a circle are refused with `LINK_CYCLE`. The components of LINK-003 are not computed. |
| Initialization | A module's initializers run after those of every module it depends on, and its finalizers before theirs; within a module the order is its own. |
| Storage | Every module keeps its data segments and its thread-local segments. A module two others depend on is in the program once, and both see the one. |
| Capabilities | The linked program declares what any of its modules declares. |
| Personality (RT-003) | A module's manifest says which personality it is for, and which foreign processor's code it comes with, if any. The modules of a program must say the same of both: `LINK_PERSONALITY` otherwise. The process has the personality of its program. A host may say which personality its processes are to have (`smir-run --personality`, the `personality` of a context of the C interface), and a program for another is then not run (`EXEC_PERSONALITY`, or `ENOEXEC` from `process_create`); the machine the runtime is on never decides. Portable code does the same under every personality: what the choice changes belongs to foreign domains, of which there are none yet, and a module that says it comes with foreign code is loaded like any other as far as its portable part goes. |
| Selection | None: groups, COMDAT, common and weak definitions are settled by the compiler within a module, never between modules. Two modules may define functions of the same name; a call reaches the one in the module that answers the caller's dependency. |
| Identity | The SHA-256 of `SMIR-LINKED\0` and then the identity of each module in the order given. Compiled code is for the linked program and for nothing else. |
| A module that is not linked | A module with a function declaration of a dependency is a valid object and is not a program: running it, compiling it and starting a process of it are refused with `EXEC_UNLINKED`. |
| When | Before the process starts. Nothing is loaded into a process that runs, and nothing is unloaded. |

## Portable services, capabilities and errors

RT-001: [services-v1.json](schema/runtime/services-v1.json) is the complete executable
catalog of 59 portable service records: exact namespace/name/version, input and
result types, capability, scalar constraints, buffer directions/length indices,
handle kinds, irreversibility and blocking behavior. `services_build.py` is its
source. All service `abi` fields are None: compiler-internal multi-result status
signatures are not source C call signatures. Ordinary hosted C/C++ wrappers have
independent source ABI plans and translate results/errno normally.

Every declared capability is mandatory and must be granted independently by the
context; metadata does not self-grant or silently intersect away requirements.
Requirement triples `(kind,name,positive exact version)` are sorted/unique.
Closed kinds are runtime, feature, catalog, library, native_image, personality,
host. Actual registered support for the exact version is required, not >=,
wildcard or file-created registration. Native-image names are lowercase SHA-256.

Service status 0 is success; positive errors use the pinned LLVM/Linux errno
numeric domain. [errno-v1.json](schema/runtime/errno-v1.json) contains explicit
Linux/Darwin/Win32/NTSTATUS conversion tables extracted from archived primary
headers. Unknown native error maps to EIO while retaining native cause in the
diagnostic record. Unknown portable status rejects. Host macro casts and a host
OS default are not adapters. Each guest thread owns its errno independently.

`memory.map` returns `(status,data_ptr)`; success publishes the actual fresh
pointer in the same ticket, never an integer requiring a fictional exposure.
`module.symbol` has five arguments: module handle, namespace bytes/length, name
bytes/length. Its descriptor is the source CALL_SIGNATURE of the returned
`code_ptr<S>`; `module.data_symbol` instead names nominal T. All other service
descriptors are None. Actual selected provider type/source signature must match
before issuing pointer/code authority; name lookup alone is insufficient.

All buffers are counted guest UTF-8/byte spans; validate lengths, permissions,
nonwrapping ranges and required terminators/structure fields before irreversible
effects. Zero-byte spans do not dereference a pointer. Stream staging is bounded
at 65536 B per request. Time is 16 B, file metadata 128 B, space metadata 32 B;
exact LE fields/reserved zeros and directory record framing are catalogued and
validated by `services.py`. No host `struct stat`, `timespec`, locale or directory
layout crosses the portable ABI. Spawn input is an ordered revision-1 record
with artifact, UTF-8 arguments/environment/cwd and explicit inherited handles.

An embedding application's custom `host_value` import has an independently
registered immutable canonical descriptor and actual execution graph. Only scalar
integer/FP and origin-free raw values are allowed. It cannot replace any smir.*
service or pass guest data/code pointers, opaque handles or aggregates. The
callback receives private captured values and builds call-bound typed results.
Pending completion commits once; foreign packets, replay and publication after
abandonment reject. Host exceptions are contained as EIO, never guest C++ EH.

### Services as implemented

[services-v2.json](schema/runtime/services-v2.json) is a second catalog, of
the services added since the first was frozen: so far `thread.concurrency`.
It has the form of the first and an identity of its own, the same digest
with `SMIR-SERVICES-V2\0` before it. An import quotes the identity of the
catalog its service is in, so the first catalog, and every object that
quotes it, is as it was; a service has one catalog.

The interpreter in `crates/smir-portable` performs twenty-two services:
`file.read`, `file.write`, `file.open`, `file.close`, `file.seek`,
`file.unlink`, `file.rename`, `process.exit`, `process.abort`, `clock.now`,
the six `thread` services of the first catalog and `thread.concurrency` of
the second, the two `sync` services and the three `memory` services. A module that imports any
other service is valid and is refused as unimplemented when it is loaded. The
catalog leaves the following open; the interpreter settles them this way, and
`tests/interp/services.rs`, `tests/interp/files.rs`,
`tests/interp/threads.rs` and `tests/interp/mapping.rs` in that crate check
each one.

| Question | As implemented |
|---|---|
| Granting capabilities | The embedder supplies a host that answers for each capability. A module runs only if every capability it declares is granted; otherwise the run is refused with `EXEC_CAPABILITY` before its first step. `smir-run --program` grants `file`, `process`, `clock`, `thread`, `sync` and `memory`; its other modes grant nothing. |
| Handles | A process starts with three open handles: 0 is standard input, 1 standard output, 2 standard error. Reading 1 or 2, writing 0, and any handle that is not open fail with `EBADF`. `file.open` returns a handle that no open file has or had: a closed handle is never given out again. |
| Files | Whether there are any is the host's affair. A host without files refuses `file.open` with `ENOENT`, or with `EROFS` if the file was to be made. `smir-run --program --directory DIR` gives the program the files under DIR: that directory is the root of every path and the directory relative paths start from, `..` at the root is the root, and a path that leaves it through a symbolic link is refused with `EACCES`. |
| Paths | Names separated by `/`. A path that is not well formed is a status, not a fault: `EINVAL` for one of no bytes or with a NUL, `ENAMETOOLONG` beyond 4096 bytes, `EILSEQ` for bytes that are not UTF-8. A path the program may not read is the fault of a load of those bytes. |
| `file.open` flags | Bit 0 read, bit 1 write, bit 2 make the file if there is none, bit 3 empty it, bit 4 write at its end always. A file is opened for reading or writing at least, and is emptied or appended to only if it is written; any other combination, another bit, or a mode beyond the twelve permission bits is `EINVAL`. The mode is the permissions of a file the call makes. |
| `file.seek` | `whence` 0 counts from the start, 1 from the position, 2 from the end; another value and a position before the start are `EINVAL`. A standard stream has no position: `ESPIPE`. |
| A poison or undef argument | Undef refines to zero, or to the null pointer. A poison argument is undefined behaviour, `ub_service_argument`. |
| A buffer that fails its guard | The program stops with the fault a load or store of the same bytes would raise (`memory_bounds`, `memory_lifetime`, `memory_permission`, `pointer_provenance`), before the host does anything. The whole span the call names is guarded, including the part beyond what one call transfers. A span of no bytes is not dereferenced. |
| Shadow of bytes sent out | Undef bits are sent as zero. A poison byte among the bytes sent is undefined behaviour, `ub_service_argument`. Bytes read in are fully defined and carry no pointer origin. |
| Size of one transfer | At most 65536 bytes; a longer request transfers that many and reports the count. |
| A host failure | The status is the portable error number and the value is 0. It is never a fault. |
| `thread.concurrency` | How many of the program's threads run at one time: what the embedder says (`smir-run --processors N`), or else what the machine the engine is on runs at once; at least 1 and at most the 1024 threads a program may have. It is what the program is told, not a limit: a program told 1 that starts eight threads has eight threads running. |
| Clocks | `clock.now` returns the host's reading in nanoseconds. A clock identifier outside 0 to 3 is the status `EINVAL`, not a fault. The runner's processor-time clocks read the time since the first clock reading of the run: an interpreted program's processor time is the time it has been running. |
| `process.exit` modes | 0 is clean, 1 quick, 2 immediate. A clean exit runs the module's finalizers first; the engine knows of no other cleanup, so the other two end the run at once. Another mode is the trap `service_argument`. |

Mapped memory, as implemented:

| Question | As implemented |
|---|---|
| What a mapping is | `memory.map` creates a new object of the size asked, at an address that is a multiple of the alignment, whose bytes are defined zeros. The base it returns is a pointer to that object, like the address of any other; an access through it is guarded the same way. |
| Permissions | Bit 0 permits reading and bit 1 writing; a mapping may permit both, one or neither. An access the mapping does not permit is the trap `memory_permission`. An atomic read-modify-write needs both. |
| Requests that make no sense | A size of zero, an alignment that is no power of two, or a permission bit beyond those two is the status `EINVAL`. |
| The memory limit | Mapped bytes count against the run's limit on live memory, with every other object. A mapping that would exceed it is the status `ENOMEM` with a null base, not a fault. Unmapping returns the bytes. |
| `memory.unmap` and `memory.protect` | Each takes the base of a mapping and its whole size; anything else (part of a mapping, an object that was not mapped, a mapping already unmapped) is the status `EINVAL` and changes nothing. After `memory.unmap` every pointer into the mapping is a pointer to an ended object: an access traps with `memory_lifetime`. `memory.protect` keeps the contents. |

Threads and waiting, as implemented:

| Question | As implemented |
|---|---|
| What a thread is | Every guest thread runs on a host thread of its own; the threads of a program run in parallel and share its memory, its host and its limits. The host is asked for one effect at a time: a thread that waits for input keeps the others from the host until it has it. |
| A thread's entry | `thread.spawn` takes a code pointer to a function that takes one data pointer and returns one 64-bit integer, whatever type the pointer is passed under. Anything else, the null pointer included, is the status `EINVAL`. The new thread calls the function with the argument given; what it returns is the thread's result. |
| `stack_bytes` | Reserves nothing: an activation's storage is not carved out of one stack. The call depth limit applies to each thread, and stack objects count against the memory limit like any object. |
| Handles and identities | The first thread has identity 1 and no handle. The handle `thread.spawn` returns is the identity `thread.id` reports in that thread; handles count up from 2 and are not reused. A program has at most 1024 threads at a time; one more is the status `EAGAIN`. |
| Joining and detaching | `thread.join` waits for the thread to end and returns its result; the handle is then invalid. A join of the calling thread is `EDEADLK`. A join or detach of a handle that names no joinable thread, or that a join has already claimed, is `EINVAL`. |
| `thread.exit` | Ends the calling thread with the result given, from any depth of calls; the stack objects of its activations end with it. In the first thread it ends the program normally with status 0. |
| The end of the program | The program ends when its first thread returns from the entry function, when any thread calls `process.exit` or `process.abort`, or when any thread faults or reaches a limit; the outcome is that thread's. The first thread to end the program decides the outcome. The other threads stop at their next step and are not waited for beyond that. A clean end runs the finalizers once, on the thread that ended the program, while the other threads still run. |
| `sync.wait32` | The address is a multiple of four (otherwise the trap `service_argument`) and its four bytes are guarded like a load. If the word holds the expected value the thread waits for a wake on that address; comparing and starting to wait are one action with respect to `sync.wake32`, so a wake that follows a store to the word is never lost. A word that holds anything else, an unspecified value included, is the status `EAGAIN`. A timeout of 0 does not wait and the greatest 64-bit value waits without a deadline; a wait whose time passes is `ETIMEDOUT`. |
| `sync.wake32` | Wakes up to `count` of the threads waiting on the address, those that have waited longest first, and returns how many. The address is guarded as for a wait. |
| A program that cannot go on | A thread that joins, or waits without a deadline, is parked. If every thread of the program is parked, nothing can happen any more, and the run ends with the outcome `deadlock` instead of never returning. A wait with a deadline does not park. |
| Limits | The step limit covers the steps of all threads together. Threads take steps out of it 4096 at a time, so with several threads the limit can be reported while that many steps per other thread are still untaken; the count reported is of steps actually taken. |
| Thread-local storage | A `call` of an import of `tls_address_raw` yields the address its offset operand names in the calling thread's copy of the segment the import's target names; any offset is representable, and the address is checked when it is used. A thread's copy of a segment is a new object that starts as the segment's image, created when the thread first asks for an address in it and ended with the thread, so a pointer into it that outlives the thread traps like any pointer to an ended object. Only static initialization is performed: a segment with initializer or destructor functions, or a relocation in a segment, is refused as unimplemented. |
| Determinism | A program that starts no thread runs the same way every time. One that does can end differently from run to run, as its interleaving decides; the engine adds no synchronization beyond what each operation needs to be one step. |

Functions of the host, as implemented (`tests/interp/hosts.rs` in that crate
checks each row on both engines):

| Question | As implemented |
|---|---|
| What a host function is | An import of `kind` `host`: an application's own function, named by namespace, name and version, over integers of up to 128 bits and floats. A module that imports one over raw bytes is valid and is refused as unimplemented when it is loaded. |
| The descriptor | The canonical `runtime_host_descriptor` record: revision 1, the function's namespace, name and version, a root of types of its own with no memory layouts, and the function type in it, of the portable calling convention and not variadic. Its identity is the SHA-256 of `SMIR-HOST-V1`, a zero byte and the record. An import quotes that identity; a host registers the function with the record. A descriptor describes an import if the identities are equal, the names and versions are, and the parameters and results are the same types with the same `noundef`. |
| Which host | A process is started only under a host that has every host function its module imports (`EXEC_IMPORT` otherwise, before the first step), and grants `host_value`, which such a module declares. No host is asked about a function at any later time, and none is found by name alone. |
| Arguments | The host gets the bits of each. An unspecified value goes as zero; a poison argument is undefined behaviour, `ub_host_argument`, and the host is not called. |
| Results | The bits of each result, within the width of its type. A host that fails, or returns another number of results, or bits beyond a width, ends the program with the trap `host_call`: the function's own results have no room for a failure. |
| Threads | The host is asked for one effect at a time, as for the services: a thread that waits for a host function keeps the program's other threads from the host until it has its answer. |
| Linking | Each module of a linked program keeps its own imports; two that import the same function both do. |

The initializers of section 2 run before the entry function, in ascending
`(priority, ordinal)` order, and the finalizers in the descending order after
the entry returns or the program exits in the clean mode. An initializer or
finalizer that does not return ends the run with its own outcome. One with an
association is refused as unimplemented. Between the modules of a linked
program the order is that of "Linking as implemented": a module's
initializers after those of the modules it depends on.

An object has no entry. To run one as a program, the runner calls its exported
function `_start`, which has the execution signature of the CRT entry
described below, `i32(i32, data_ptr, data_ptr)`: an argument count, the
argument vector and the environment vector. The compiler generates it for
every program that defines `main`: it calls `main` with as many of the three
as `main` declares, then calls the C library's `exit` with the result, or
returns the result when no library is linked. It carries no `noundef`, no
source ABI plan and no manifest reference, so it is not yet the entry of an
image. An object without `_start` is entered at its exported `main`, which
must be `i32()` or `i32(i32, data_ptr)`.

The runner builds both vectors in one new mutable object: one pointer per
argument and a null pointer after the last, then the environment vector,
which is one null pointer because the environment is empty, then each
argument's bytes with a terminating zero.

## Nonlocal exits, CRT and termination

The source `jmp_buf` is canonical C23 builtin array-one of `rax.jmp_state` in
both C23 and C++23 producers. Source parameter adjustment passes the state
address. The selected state record is 32 B aligned 8 B: revision u32=1 at0 B,
reserved u32=0 at4 B, process/checkpoint/generation u64 at8/16/24 B. Its actual
source declaration and execution transport follow INT032/ABI030REV6; source
wrapper and underlying state are distinct nominal types. It names a runtime-issued private checkpoint,
not a native stack image. Longjmp requires same process/thread and live original
activation/module/binding generation. Input i32 0 becomes 1. It restores the
saved concrete SSA checkpoint, a permitted refinement of indeterminate changed
nonvolatile automatic values; it does not roll back memory, errno or fenv.
Volatile/globals/heap retain current contents. Ended lifetimes never revive;
stack allocations created after capture are revoked. A C++ path requiring a
nontrivial destructor is UB and rejects before mutation, including obligations
created later in the same activation. `sigsetjmp` additionally saves exactly
128 B selected-personality mask state; dynamic source save-mask choice lowers
to explicit setjmp/sigsetjmp branches. Ordinary setjmp leaves current mask.

An image has one self-referenced compiler-generated CRT entry; an object has no
entry. Execution signature is `i32(i32,data_ptr,data_ptr)` with all noundef true,
portable/nonvariadic, escape=terminate and no_return=false. Source signature is
C `int(int,char**,char**)`, no this/VTT/varargs. `argc=1+argument_count <= INT_MAX`;
argv[0] is logical manifest name. Writable strict UTF-8 NUL strings and 8 B-aligned
pointer arrays end in null pointers; env names are unique/nonempty and exclude
NUL/equals. Windows UTF-16 conversion rejects unpaired surrogates; invalid POSIX
UTF-8 reports EILSEQ. Startup objects live through process lifetime. Initialization
occurs once before main, in the same logical guest thread with default fenv and
errno 0; library first-start initialization uses equivalent once/wait semantics.

Normal exit stops new entries/workers, completes current-thread TLS cleanup,
reverse at_exit/__cxa registrations and required module finalization. Quick exit
runs only quick-exit registrations; immediate exit runs neither. Other threads
stop cooperatively without invented stack destructors. Pending host operations
drain privately without late guest copyout. Public EXIT is not observable while
owner-dependent guest cleanup can still run; retained host exception owners keep
the process closing/finalize busy. Unix host status is low 8 bits of original i32;
Windows status is its u32 representation; the portable result retains full i32.

Source exception ownership, caught/uncaught state, termination dispatch and typed
cleanup are specified in [08-jit.md](08-jit.md), not delegated to host C++ TLS.

The sysroot as built so far is LLVM libc alone, in its freestanding
configuration, as LLVM bitcode that the compiler links into each program; see
[tools/smir-clang](../../../../tools/smir-clang/README.md). Its embedder
hooks are a C file over the runtime services, and its threads (`pthread.h` and
`threads.h`) another, over the `thread` and `sync` services, since LLVM libc's
own are written for the Linux kernel. compiler-rt's builtins are not
needed: the format has 128-bit integer operations, and the engine computes
binary128. For C++ the sysroot has libc++'s headers and, as a second bitcode
library, the part of libc++ that is compiled separately: containers,
strings, algorithms, threads, and the stream classes over the standard
streams and over strings, in the "C" locale. Under it are libc++abi's
descriptions of types and its exception classes, and a runtime for
exceptions that needs no unwinder, because the compiler makes exceptions
ordinary control flow. libunwind is not built. There are no wide
characters, and of `std::filesystem` only what is in its headers.

The C library's streams are LLVM libc's own, which buffer and lock, over a
platform layer of a few functions on the `file` services: `fopen` and its
relatives open, position, rename and remove files in whatever namespace the
host gives the program. Standard output is written line by line and when
input is asked for, standard error at once, and everything a stream still
holds when the program ends in good order is written then, after the
program's own finalizers.

A bitcode library is one module, but a program gets from it what it would
get from an archive of object files: the definitions it lacks, and the
constructors and destructors of static objects only of those source files
it takes something from. A program that names no stream therefore
constructs none.

RT-002: The sysroot consists of pinned LLVM libc, compiler-rt builtins, libc++,
libc++abi and libunwind ported to the declared guest ABI/services/private EH.
Libunwind is a required dedicated RAX-adapted source component, with the selected
`rax_logical_libunwind` backend. Its port must use the existing typed logical
SEARCH/CLEANUP, private-E and journal protocols, together with admitted
foreign-domain personalities and their independent code/build/CFI/lease evidence.
This selection does not provide unmodified native `_Unwind` header/binary ABI
compatibility or a host stack unwinder fallback. It preserves the selected
portable ABI site and its LLVM-unwinder/static-unwinder configuration.
Pinned LLVM/libc/libc++/libc++abi gaps and frontend integration remain explicit
[LLVM contract](09-llvm.md) obligations. Contract/reference validation is separate
from implementing those libraries or the production runtime.

Assumptions: all six runtime roots have matching independently admitted execution/
ABI roots and immutable artifact bytes; stress with inconsistent actual graphs,
wrong private IDs and reordered deployment. High-impact boundary: incomplete full
call-plan joins or disconnected selection redirects block compiler freeze. Medium:
registered host callbacks are deliberately scalar-only; pointer services use the
portable catalog. Low: deterministic reference schedules are not host qualification.

## CodeAddress metadata refinement (current compiler contract)

`function_address` denotes a source Function address expectation, independently
of a callable ABI plan. Its executable type is `code_address`; source linkage is
C or CPP, nominal is mandatory and abi_signature is absent. Size is absent,
alignment is1, and COMDAT/fallback are absent. Undefined strong/weak/external_weak
expectations are allowed; a definition is exclusively a native descriptor with
strong/weak binding. Alias, common, DATA/TLS/import and portable-function body
definitions are rejected. A native descriptor retains its actual source domain,
image, byte range and selected foreign ISA; descriptor bytes never establish
callable ABI/bridge evidence.

A `code_address` leaf targets an actual ordinary function/import/function_address
symbol or the corresponding original consumer declaration. Width is8bytes,
integer_bits0, addend0, and derivation/check_base/flags/inrange are empty/false.
DATA/TLS source namespaces and actual extents are checked independently; every
leaf and constant initializer participates in the same overlap check. A dependency
address expectation cannot weaken an ordinary call expectation: call signatures
retain their own mandatory execution Fn and caller plans stay in the original
caller namespace. Function.execution is optional and cannot supply a missing plan.

Static metadata proof preserves unresolved SymbolBinding and LeafRelocation
requirements. It does not issue AddressAuthority, WeakAbsent or BindingPermit.
The currently qualified Rust metadata profile admits only the exact strong CPP
SELF nominal/direct ordinary Function and full8-byte DATA patch conjunctions
reported by its real factory tests. Other valid forms remain UnavailableEvidence.
Runtime publication requires original actual selection, target owner/generation,
process allocator reservation and the actual issuer; old dictionary resolvers are
insufficient and return code_address_unavailable before publication.
